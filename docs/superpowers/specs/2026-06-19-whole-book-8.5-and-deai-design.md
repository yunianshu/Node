## 1. 背景与诊断

### 1.1 现状（基于 novels10-13 实测数据）

| Book | 逐章均分 | **整本终审分** | 主要失分维度 |
|---|---|---|---|
| novels13 | 8.59 | **5.8** ❌ | foreshadowing_payoff=4, world_consistency=4, pacing_curve=4 |
| novels12 | 8.63 | **7.0** ❌ | pacing_curve=6.0, world_consistency=6.0 |
| novels10 | 8.50 | — | 35% 章节低于 8.5 |

**核心矛盾**：逐章 reviewer 已能稳定给出 ~8.5，但整本 `book_reviewer` 的 8 维度加权综合分只有 5.8-7.0。两者严重脱节。

### 1.2 失分维度的根因（来自 novels13 终审报告实证）

整本终审的扣分几乎全部集中在**大纲层结构缺陷**，而非正文句子质量：

1. **伏笔悬空（foreshadowing_payoff=4，权重15%）**
   - "战无双杀气失控伏笔（第7章）完全悬空，结局未提及"
   - "守墓人第23章后消失未交代结局"
   - "混沌之环'第四元'缺陷（第20章伏笔）未修复"

2. **逻辑矛盾（world_consistency=4，权重10%）**
   - "身份悖论：苏长空究竟是混沌的创造物还是天地的产物？第13章 vs 第29章设定冲突"

3. **注水腰（pacing_curve=4，权重15%）**
   - "第12-17章陷入反复势力博弈、回忆闪回、信息解释，连续6章缺乏 catalyst 式转折"

4. **配角弧线断裂（character_arc，权重15%）**
   - "姬雪潇弧线断裂：神凰转世→创造本源碎片，未展现身份心理挣扎"
   - "战无双杀气失控伏笔从未引爆"

### 1.3 为什么 writer 无法修复这些问题

`writer.py` 受 `【必须严格执行的关键事件清单】` 硬约束，只能执行大纲规定的 `key_events`/`chapter_hook`/`story_beat`。若大纲遗漏伏笔回收或制造逻辑矛盾，writer 无权补救。**真正的杠杆在 `outliner.py` 和大纲层校验。**

### 1.4 现有大纲层基础设施（避免重复造轮子）

已存在但未充分利用的能力：
- `scripts/core/outline_memory.py`：派生前序大纲记忆，含 `recent_foreshadowing`（仅传递，不强制回收）。
- `scripts/maintenance/outline_book_reviewer.py`：分层大纲审查（segment→volume→final），多轮投票，**已追踪 `open_threads`**，但**只报告不强制闭环**——dangling 线程被传递下去，从未要求回收。
- `scripts/pipeline/outliner.py`：已有 `story_beat` 救猫咪节拍枚举 + "禁止注水腰" 文字警告，但无结构化伏笔台账。

**缺口确认**：全管线没有"伏笔回收强制机制"和"全书闭环门禁"。这是 Part A 要补的核心。

### 1.5 研究依据

- **StoryScope（马里兰大学 + Google DeepMind，2026-04，arXiv:2604.03136）**：仅用 30 个**叙事决策特征**即可 93.2% 准确率检测 AI 小说。AI 小说的特征是"过度解释主题、偏好工整单线剧情、叙事储备窄"。**结论：表面风格修复无效，必须从叙事结构决策层入手。**
- 中文 AI 网文通病实证：排比抒情、总结性收尾、元叙述、形容词堆砌、配角符号化。

## 2. 设计总览

两部分并行，分别打两个评分口径：

```
┌─────────────────────────────────────────────────────────────┐
│  Part A: 大纲层结构闭环  →  整本终审分 ≥ 8.5（主杠杆，60%+权重）  │
│  ┌──────────────┐   ┌──────────────────┐   ┌──────────────┐ │
│  │ A1 伏笔台账   │→→│ A2 全书闭环校验    │→→│ A3 配角弧线   │ │
│  │ ledger.json  │   │ audit + 补丁回写  │   │ 规划注入     │ │
│  └──────────────┘   └──────────────────┘   └──────────────┘ │
│         ↑ 注入约束              ↑ 门禁阻断 writer              │
└─────────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────────┐
│  Part C: 正文去AI味     →  逐章均分 ≥ 8.5（保证口径二）        │
│  ┌──────────────────┐   ┌──────────────┐   ┌──────────────┐ │
│  │ C1 AI味本地检测   │→→│ C2 reviewer  │→→│ C3 writer    │ │
│  │ 确定性，不耗API   │   │ 增 ai_flavor │   │ 去AI味重写分支│ │
│  └──────────────────┘   └──────────────┘   └──────────────┘ │
└─────────────────────────────────────────────────────────────┘
```

### 2.1 流程集成点（coordinator）

现有流程：`planner → outliner → outline_reviewer → writer → reviewer → book_reviewer`

新流程：`planner → outliner → outline_reviewer → outline_book_reviewer → 【A2 foreshadowing_audit 门禁】→ writer → reviewer(+C1/C2) → book_reviewer`

A2 是 writer 之前的**最后一个大纲阶段硬门禁**。它需要全书大纲已全部生成，因此排在所有大纲生成与审查之后、writer 之前。它与 `outline_book_reviewer` 无依赖关系（A2 扫大纲文件即可），二者先后均可，但 A2 必须在 writer 之前完成。dangling 线程超阈值则阻断 writer。

## 3. Part A 详细设计 — 大纲层结构闭环

### 3.1 A1：持久化伏笔台账 `foreshadowing_ledger.json`

**新建 `scripts/core/foreshadowing_ledger.py`**

#### 3.1.1 台账数据结构

存于 `projects/<book>/reports/foreshadowing_ledger.json`：

```json
{
  "version": 1,
  "book_id": "novels14",
  "total_chapters": 60,
  "threads": [
    {
      "id": "F001",
      "planted_at": 7,
      "setup": "战无双隐瞒杀气失控，暗示未来暴走",
      "category": "character_internal",   // character_internal|world_rule|plot_mystery|power_system|relationship
      "priority": "major",                // critical|major|minor
      "status": "planned_resolution",     // planted|planned_resolution|resolved|dangling
      "must_resolve_by": 26,              // 最迟回收章（基于全书进度推算）
      "resolved_at": null,
      "resolution_plan": "第26章虚无本源对峙时杀气失控→姬雪潇虚无感知稳定",
      "resolved_in_outline": false        // 是否已在大纲中落实回收
    }
  ],
  "stats": {
    "total": 42,
    "resolved": 38,
    "dangling": 4,
    "critical_dangling": 1
  },
  "updated_at": "2026-06-19 10:00:00"
}
```

#### 3.1.2 台账读写 API

```python
# scripts/core/foreshadowing_ledger.py

def load_ledger(project: Path) -> dict: ...
def save_ledger(project: Path, ledger: dict) -> None: ...  # atomic_write_json

def register_thread(ledger: dict, *, planted_at: int, setup: str,
                    category: str, priority: str, must_resolve_by: int) -> str:
    """登记新伏笔，返回 thread_id（自增 F00X）。"""

def resolve_thread(ledger: dict, thread_id: str, *, resolved_at: int,
                   resolution: str) -> None: ...

def dangling_threads(ledger: dict, *, as_of_chapter: int | None = None) -> list[dict]:
    """返回所有未回收且已过 must_resolve_by 的线程。"""

def compute_must_resolve_by(planted_at: int, total_chapters: int,
                            category: str) -> int:
    """根据伏笔类型 + 全书进度推算最迟回收章。
    - character_internal: planted + 总章数的40%
    - plot_mystery: 中点(midpoint)之前
    - world_rule: finale 之前
    - relationship: planted + 25%
    """
```

#### 3.1.3 台账构建时机

两处构建/更新台账：

1. **outliner 生成时**（见 3.4）：outliner 解析生成的 outline JSON，自动提取 `foreshadowing` 字段 → 登记/回收线程。
2. **A2 audit 阶段全量重建**（见 3.2）：扫全书大纲，对账修正。

### 3.2 A2：全书闭环校验 `scripts/maintenance/foreshadowing_audit.py`

**独立脚本，在 outline_book_reviewer 之后、writer 之前运行。**

#### 3.2.1 三阶段流程

```
阶段1 重建台账：scan_outlines() → ledger
        ↓
阶段2 标记悬空：dangling = threads where status != resolved AND chapter > must_resolve_by
        ↓
阶段3 生成补丁：对每条 dangling，调 LLM 生成"回收 edit ops"（指定插入章 + 情节）
        ↓
阶段4 回写大纲：apply patches to outline JSON + 更新台账
        ↓
阶段5 门禁判定：critical_dangling == 0 ? pass : block
```

#### 3.2.2 回收补丁生成 prompt（核心）

```
你是长篇小说的伏笔回收专家。以下伏笔在大纲中埋下但未回收，请在指定章节大纲中
插入回收情节，【不得改动已有主线】，只在指定章节的 key_events 或 foreshadowing 字段
增量补内容。

待回收伏笔：
{id, setup(埋设于第X章), category, priority}

指定回收章：{target_chapter = min(must_resolve_by, total_chapters)}

要求：
1. 回收必须自然融入该章已有剧情，不能突兀
2. 回收要制造情感/信息回报，不能一笔带过（"他终于明白了"=无效回收）
3. 输出 JSON edit ops：
   {"thread_id": "...", "target_chapter": N,
    "key_events_addition": ["新增关键事件描述"],
    "foreshadowing_update": "回收后的伏笔字段文本",
    "resolution_summary": "50字内回收说明"}
```

#### 3.2.3 门禁规则

- `critical_dangling > 0` → **阻断 writer**，要求人工或自动补丁后重审
- `major_dangling > 阈值（默认3）` → 阻断
- `minor_dangling` → 仅警告，不阻断
- 补丁应用后自动重跑阶段1-2，直到通过或达重试上限（默认3轮）

#### 3.2.4 CLI

```bash
python scripts/maintenance/foreshadowing_audit.py \
  --project projects/novels14 \
  [--force]              # 忽略缓存台账，全量重建
  [--apply-patches]      # 自动应用回收补丁（默认只报告）
  [--max-rounds 3]       # 补丁重试上限
  [--block-threshold 0]  # critical dangling 阻断阈值
```

退出码：0=通过，1=dangling 超阈值（阻断）。

### 3.3 A3：配角弧线规划注入

#### 3.3.1 outliner prompt 增量

在 outliner 的全书规划阶段，注入"配角弧线检查表"。从 `characters.json` 提取所有有名配角，要求大纲为每个配角规划：

```json
"character_arc_plan": {
  "姬雪潇": {"intro": 1, "turn": 15, "climax": 29, "resolution": 30,
             "arc_summary": "神凰转世→身份困惑→接受本源碎片使命"},
  "战无双": {"intro": 1, "turn": 7, "climax": 25, "resolution": 30, ...}
}
```

每章大纲生成时，outliner 必须检查本章是否触及某个配角的 `turn`/`climax`/`resolution` 节点，若是则必须落实对应弧线推进。

#### 3.3.2 outline_book_reviewer final_review 增维度

在 `outline_book_reviewer.py` 的 `final_review` prompt 中增加校验项：
- 每个有名配角是否有 intro→turn→climax→resolution 完整弧线？
- 是否存在配角"出场后消失"（intro 后 N 章无提及）？

### 3.4 outliner.py 改动

#### 3.4.1 台账注入 prompt

生成第 N 章大纲时，调用 `dangling_threads(ledger, as_of_chapter=N)`，将所有"本章应回收"的线程注入 prompt：

```
## 【本章必须回收的伏笔】（强制要求）
以下伏笔已过最迟回收章，本章必须回收至少一条，否则视为大纲不合格：
- F001（第7章埋下）：战无双杀气失控——回收计划：第26章虚无本源对峙时失控→姬雪潇稳定
- F005（第12章埋下）：混沌之环第四元缺陷——回收计划：...

本章 foreshadowing 字段必须包含所回收伏笔的 id 与回收说明。
```

#### 3.4.2 台账更新钩子

outliner 写入 `chapter_XXXX.json` 后，解析该章 `foreshadowing` 字段：
- 若字段包含"回收 F00X"或语义匹配已有线程 → `resolve_thread()`
- 若字段是新伏笔 → `register_thread()`，`must_resolve_by` 由 `compute_must_resolve_by()` 推算

为支持语义匹配，约定 foreshadowing 字段格式：
```
埋设：[埋]战无双杀气失控（F007）
回收：[收]F003 苏长空身世之谜——揭示为混沌投射
```
`[埋]`/`[收]` 前缀 + 伏笔 id 是机器可解析的强约定。

## 4. Part C 详细设计 — 正文去AI味

### 4.1 C1：AI味本地检测器 `scripts/core/ai_flavor_detector.py`

**确定性检测，不耗 API，可在 reviewer 前作为快速预筛。**

#### 4.1.1 检测维度（基于 StoryScope 30特征 + 中文网文通病）

```python
def detect_ai_flavor(text: str) -> dict:
    """
    返回：
    {
      "ai_flavor_score": 7.2,      # 0-10，越高越不像AI（与reviewer口径一致）
      "issues": [
        {"type": "parallel_sentiment", "severity": "major",
         "location": "第3段", "evidence": "不仅…而且…更…连续排比",
         "suggestion": "打破工整，改为长短句交替"},
        {"type": "summary_ending", ...},
        ...
      ],
      "metrics": {
        "parallel_density": 0.8,       # 排比密度（处/千字）
        "adjective_pileup": 1.2,       # 高频AI形容词密度
        "paragraph_length_variance": 0.3,  # 段落长度方差（低=工整=AI味）
        "meta_narration_hits": 2,      # 元叙述命中数
        "telling_not_showing": 3       # "他感到/他明白"类告知数
      }
    }
    """
```

#### 4.1.2 检测规则（确定性正则 + 统计）

| 维度 | 规则 | 阈值 |
|---|---|---|
| `parallel_sentiment` | 连续≥3个"不仅…而且…更…" / "…的…的…的" / "只要…就…只要…就…" | ≥1处/章 → major |
| `summary_ending` | 章末300字内匹配元叙述词表："就这样""故事才刚刚开始""他明白了""一切都有了答案" | ≥1 → major |
| `adjective_pileup` | 高频AI形容词密度：璀璨/磅礴/恐怖/惊天/震撼/无与伦比/亘古/浩瀚 | ≥2/千字 → minor |
| `low_variance` | 段落字数方差/均值 < 0.4（过于工整） | → minor |
| `meta_narration` | "作为""以下是""本章完""字数："等生成痕迹 | ≥1 → major |
| `telling_not_showing` | "他感到/他意识到/他明白了/心中涌起" | ≥3/章 → minor |

综合 `ai_flavor_score` = 10 - 加权扣分。

#### 4.1.3 词表可配置

高频AI形容词、元叙述词表存于 `scripts/core/ai_flavor_lexicon.json`，支持项目级覆盖（`projects/<book>/ai_flavor_lexicon.json`），适配不同题材（玄幻 vs 都市用词不同）。

### 4.2 C2：reviewer.py 增 ai_flavor 维度

#### 4.2.1 scores 增字段

reviewer 的 JSON schema 增加：
```json
"scores": {
  ...现有维度...,
  "ai_flavor": "去AI味程度（0-10。越高越自然。参考本地检测证据）"
}
```

#### 4.2.2 本地检测证据注入 prompt

reviewer 调用 LLM 前，先跑 C1 检测，把结果作为 `local_analysis` 的一部分喂给 reviewer：

```json
"local_analysis": {
  ...现有...,
  "ai_flavor_detection": {
    "ai_flavor_score": 6.5,
    "issues": [{"type": "parallel_sentiment", "location": "第3段", ...}]
  }
}
```

prompt 增加指令：
```
## 【AI味专项审查】
本地检测发现以下AI味问题（见 local_analysis.ai_flavor_detection）。
若 ai_flavor_score < 7，verdict 不得为"通过"，必须在 edits 中给出针对性重写：
- 排比抒情 → 拆成长短句 + 具体动作
- 总结收尾 → 改为悬而未决的钩子
- 形容词堆砌 → 替换为可感物象
```

### 4.3 C3：writer.py 去AI味重写分支

#### 4.3.1 触发条件

writer 的 `generate_chapter` 重写路径中，若 `review_data["scores"]["ai_flavor"] < 7` 或本地 C1 检测 `ai_flavor_score < 7`，走专用重写 prompt。

#### 4.3.2 专用重写 prompt（增量于现有 is_rewrite system prompt）

```python
def _deai_rewrite_directives(detection: dict) -> str:
    """根据 C1 检测结果生成针对性去AI味指令。"""
    parts = ["## 【去AI味专项重写】（本次重写的首要目标）"]
    for issue in detection["issues"]:
        if issue["type"] == "parallel_sentiment":
            parts.append(f"- 第{issue['location']}：打破排比工整。"
                         "把'不仅…而且…更…'改为长短句交替，"
         "用一个具体动作或物象替代抒情（'他把杯子转了三圈' > '他心中涌起波澜'）")
        elif issue["type"] == "summary_ending":
            parts.append("- 章末禁止总结性收尾。最后一句必须是未解决的问题、"
                         "突然出现的威胁或未说出口的话，禁止'故事才刚刚开始'式元叙述")
        elif issue["type"] == "adjective_pileup":
            parts.append("- 删除'璀璨/磅礴/恐怖'等空泛形容词，"
         "每个形容词都要能换成具体感官细节（'空气冷得像含着铁片' > '空气无比冰冷')")
        elif issue["type"] == "low_variance":
            parts.append("- 段落长度必须有变化：穿插1-2句的短段落制造停顿，"
                         "再用长段落铺陈，禁止所有段落长度相近")
    return "\n".join(parts)
```

#### 4.3.3 重写后复检

writer 重写保存前，再跑一次 C1 检测。若 `ai_flavor_score` 仍未提升（低于原文），回退保留原文（避免越改越差）。

## 5. coordinator.py 集成

在现有 outline 阶段后、writer 阶段前，插入 A2 门禁：

```python
# coordinator.py 流程伪代码
def run_outline_phase():
    run_script("outliner.py", ...)
    run_script("outline_reviewer.py", ...)
    run_script("outline_book_reviewer.py", ...)  # 现有

def run_foreshadowing_gate():  # 新增
    """A2 门禁：伏笔闭环校验，阻断 writer 直到通过"""
    rc = run_maintenance_script("foreshadowing_audit.py",
                                "--project", project, "--apply-patches")
    if rc != 0:
        notify("伏笔闭环门禁未通过，阻断 writer。请检查 ledger.json")
        return False
    return True

def run_writer_phase():
    if not run_foreshadowing_gate():
        return
    run_script("writer.py", ...)
    run_script("reviewer.py", ...)  # 内含 C1/C2
```

C1/C2/C3 无需 coordinator 改动（嵌入 reviewer/writer 内部）。

## 8. 风险与缓解

| 风险 | 缓解 |
|---|---|
| `[埋]/[收]` 约定模型不遵守 → 台账不准 | A2 audit 阶段全量语义重建台账（不依赖 outliner 实时写入），实时写入仅作辅助 |
| 回收补丁改坏主线 | 补丁只增量改 `key_events`/`foreshadowing` 字段，不动 summary/title；补丁后重跑 outline_book_reviewer 验证 |
| C1 词表误伤（玄幻本就用"璀璨"） | 词表项目级可覆盖；C1 仅作证据，最终判定由 reviewer LLM 综合 |
| 整本流程加长（多一个门禁阶段） | A2 仅扫大纲不扫正文，开销小；补丁有重试上限 |
| 新项目 novels14 跑完整本耗时 | 先用小规模（60章）验证；A2/C 可单独小批量测（3-5章） |

## 9. 不做的事（YAGNI）

- **不做** 全书伏笔的语义相似度自动匹配（用 `[埋]/[收]` 强约定 + id 即可，语义匹配易错且耗 API）。
- **不做** writer 层的全文去AI味重写（只做增量 edit 重写，保留原文优点，符合现有增量编辑架构）。
- **不做** 新的整本评分模型（复用现有 book_reviewer，只改输入质量）。
- **不做** dashboard/reader 端改动（超出 scripts/ 边界）。
- **不做** 对 novels10-13 历史项目的回填修复（只在新项目验证，避免覆盖用户数据）。
