# 小说生成与局部修订调整

本次调整针对生成和评审共同造成的固定叙事模板，不承诺仅靠代码变化就能消除读者感受到的 AI 味。

## 行为变化

- Writer 使用当前章的事件、场景目标、结束状态和连续性资料，不再注入每章统一的紧张节点、反转、反派微反应、物象回扣与余韵配额。
- Outliner 允许单个场景、日常、过渡和安静收尾。`scenes` 仍须为非空对象数组，每项有有效的 `position` 和具体 `objective`；冲突、感官、潜台词、出口字段按需填写，可空。`tension_points` 可空，不再自动拼出前中后三个节点。
- 大纲评审和投票的硬设计门统一为 `core_desire`、`scene_design`。显式修复任务仍需验收，人物名册、因果、跨章事实检查继续保留。同节拍仅记录观察结果，不自动改标签或删除章节。
- 正文 Reviewer 阅读全文。AI 句式、人情味、关系词、场景词匹配和 origin 词匹配标记为 `advisory_only`，不直接压低总分、不自动要求补词。字数、要求角色缺失仍可拦截；模型指出的具体事实矛盾和阅读问题仍需处理。
- 关系台账作为背景事实，允许相关关系暂不出场或延后推进，不强制每章补潜台词和照料动作。
- 默认不自动使用模型给出的高分章节作风格范本，也不额外调用 Polisher。Writer 的通用二轮深化已移除；旧 `writer.deepen_rewrite` 字段不再生效。
- 现有分数门、重试次数、状态抽取和终审入口保留。整本终审及其历史修复规则未在本次全面重构，仍需在真实长篇样本上单独验证。

## 局部修改保证

Writer 返修和显式开启的 Polisher 共用 `apply_reviewed_edits`：

1. 模型只输出 JSON 补丁，所有定位以原稿为基准。
2. `old` / `after` 必须在原稿中精确且唯一，不使用模糊匹配。
3. 只允许修改审稿已指出的区域，操作类型须一致，多个补丁不能重叠。
4. 按删除范围和新增文本的较大值累计修改量，默认不超过原稿 15%。等长全文重写也会被拒绝。
5. 修改后的字数必须符合项目配置；不为凑范围截断结尾，不在补丁之外清洗全文。
6. 失败时保持原文件，返回失败供协调器报告；不回退整章重写。需要大幅结构修订的稿件应单独处理。

原稿的换行和补丁之外的文本保持不变。主流程生成新稿时的字数检查和超长压缩继续保留。

## 配置与已有项目

本地合并保留共享质量门禁、关键评分维度校验和最多四条修订任务。Reviewer 标为 `advisory_only` 的场景词匹配不会触发共享门禁；未标记的旧调用继续遵循已有阈值。局部修订的累计修改量仍受 15% 预算限制，不随任务数量增加。

新增或明确的默认配置：

```json
{
  "writer": { "use_scored_examples": false },
  "polisher": { "enabled": false },
  "revision": { "max_changed_ratio": 0.15 }
}
```

已有 `config.json` 会覆盖默认配置。如果已经显式设置 `polisher.enabled=true`，仍会进入精修，但执行的是严格补丁。

更新代码不会重写已有小说、清空报告、修改项目配置或自动刷新已达标的缓存报告。旧大纲中的具体剧情及结尾事件仍会被 Writer 尊重；若旧大纲本身已过度模板化，需要在独立副本上重新评估。`use_scored_examples=true` 可恢复旧高分样本读取行为，建议优先通过人工确认的 origin 风格素材提供参考。

## 验证与实际效果评估

```bash
python -m compileall -q scripts
python -m pytest -q
```

回归覆盖：安静单场景大纲及投票、词匹配失败不覆盖语义审稿、实际字数/角色缺失/语义矛盾仍被阻断、精确定位与修改预算、拒绝等长全文重写、不截断结尾、Writer/Polisher 文件保留，以及协调器第 4 章串行流程。

模型响应使用固定测试数据，协调器测试替换外部模型和状态抽取调用，不发送通知。它们验证实现行为，不代表真实模型文学质量已提升。

真实效果需用项目副本验证：先固定同一原稿比较新旧后处理，再固定同一大纲比较新旧 Writer。匿名阅读时检查人物声音、信息重复、刻意留悬念和固定动作等，而不是仅比较模型分数。本次仅运行隔离测试，没有调用真实模型生成或修改现有小说数据。
