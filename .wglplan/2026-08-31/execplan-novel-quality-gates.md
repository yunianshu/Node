# ExecPlan：小说正文质量门禁与修订闭环

## Goal

让后续章节只能在“正文可读、关键场景兑现、审稿结果可执行且达到高质量阈值”的条件下进入通过状态；审查不通过时，Writer 能根据完整问题集修订，而非仅改一处句子。

## Non-goals

- 不修改 `projects/` 内既有正文、提纲、评审结果或其他用户数据。
- 不调整模型供应商、密钥或生产 API 配置。
- 不添加与当前质量问题无关的 Dashboard、媒体或出版功能。

## 已验证的问题

以 `projects/novels-zhenwen` 的第 1、2 章为样本：

1. `reviewer.min_score` 为 7.0；评分达到该值就被改判为“通过”，与“高质量正文”的目标不匹配。
2. 两章的 `scene_realization_detection.rate` 均为 0.5，但 `needs_attention` 的阈值是严格小于 0.5，恰好 50% 未兑现会漏检。
3. `reviewer.py` 将所有未通过审稿意见截断为一个 `edit`，而 `writer.py` 又要求“只针对审查反馈点名的问题做局部修改”。结构、人物动机、节奏和文风类问题不能得到完整修复。
4. 审稿模型多次输出不可解析 JSON 或不可定位的原文锚点。重试耗尽后当前逻辑保留分数并写入 `invalid_review_salvaged`，导致报告同时含有无效契约与看似可信的评分。
5. 本地检测对文本质量的判断偏表面：示例正文存在套话、过度修辞和标签化反派，但 `ai_flavor_score` 仍为 10；因此不能把该分数作为通过依据。

## Proposed Changes

### `scripts/pipeline/reviewer.py`

- 将场景兑现率阈值配置化，默认要求至少 75%，并把“恰好低于目标”的情形纳入门禁。
- 新增可解释的正文质量硬门禁：人物动机/角色辨识度、因果逻辑、节奏、信息新鲜度、读欲等关键维度不足时不得通过；不再依赖表面 AI 味打分作为放行条件。
- 审稿契约失败后不再把 `invalid_review_salvaged` 当作可用质量评分；保存诊断信息但明确标记为不可通过，并给 Writer 提供标准化修订任务。
- 将审稿输出从“仅一条 edit”改为有限且可定位的修订任务集（按剧情、人物、场景、语言四类去重），保留明确上限以控制修改范围。

### `scripts/pipeline/writer.py`

- 消费标准化修订任务集，允许在不改变大纲主线和关键事件的前提下，修订受影响的连续场景，而不是仅替换一处句子。
- 增加修订后自检指令：补足字数、兑现未落地场景、修复指定人物动机/因果问题，并避免用形容词堆砌替代剧情。

### `scripts/core/workflow_state.py` 与调用方

- 将通过条件与项目配置中的正文门槛保持单一来源，避免 `reviewer.py`、状态判定和调度器采用不同阈值。
- 明确拒绝 `invalid_review*`、契约错误、未达关键维度门槛、场景兑现率不足的报告。

### `projects/<book_id>/config.json`（仅新增项目时或经用户明确授权修改）

- 增加 `quality.review_min_score`、关键维度下限、场景兑现率、最大修订任务数等配置示例；兼容没有这些字段的旧项目。

## Step-by-step Implementation

1. 读取现有配置加载路径和 Writer 重写反馈的实际数据结构，确定最小兼容配置方案。
2. 在 `reviewer.py` 提取统一的质量门禁评估函数，生成机器可读的失败原因和修订任务集；移除无效报告的分数兜底放行语义。
3. 调整 `writer.py` 的修订提示与反馈消费逻辑，使其按任务集修订受影响场景，并保留大纲、关键事件和角色状态约束。
4. 统一 `workflow_state.py`/调度调用方的通过判定，确保所有路径都使用相同门槛并拒绝无效审稿。
5. 为上述纯函数和状态判定添加轻量隔离测试；以第 1、2 章的现有产物作为只读回归样本，验证原先误放行/漏检的情形现在会失败并产出可执行修订任务。
6. 运行语法编译与测试；不触碰任何 `projects/` 正文。将实施结果和回滚点更新到本计划。

## Tests & Acceptance Criteria

- 场景兑现率为 0.5、目标为 0.75 的报告必须判定不通过，且原因明确列出未兑现场景。
- 总分达到阈值但人物辨识度、因果逻辑或读欲任一低于配置下限时，必须不通过。
- 字数、审稿 JSON 契约或 edit 锚点不合格时，状态不得为 `completed` 且不可被调度器接受。
- 非通过报告可返回 2–4 条去重、可定位的修订任务；Writer 的修订提示能完整携带这些任务，同时禁止改变大纲关键事件。
- 旧配置不含新增字段时，采用明确默认值并正常运行。
- 执行项目规定的全量 `py_compile`，并运行新增的隔离测试/只读回归验证。

## Risks & Rollback

- 门槛提高会增加重写次数与模型调用成本；通过配置项与有限修订轮数控制成本。
- 多点修订可能引入连续性风险；Writer 继续注入大纲、角色状态和关键事件约束，并在修订后重新审查。
- 回滚方式：回退本次对 `scripts/` 的提交（不触碰 `projects/` 数据）；新增配置采用缺省兼容，移除配置即可恢复默认行为。
